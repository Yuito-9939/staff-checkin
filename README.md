# 会場スタッフ入室ボード

第1会場（3F コンベンションホール）・第2会場（1F イベントホール）のスタッフ候補者が、
スマホで「入室」を押して、誰がどの会場に何人いるかをリアルタイムで共有するツールです。

- メールアドレスで登録 → メールに届くリンク（または確認コード）でログイン → 初回に氏名を入力
- 時刻に合わせて各会場のプログラムが自動で切り替わり、プログラムごとに「入室」を押せます
- 各プログラムの担当（照明係）と、その担当者が入室済みかどうかを表示します
- 管理者は、スタッフ名簿の登録・担当の割当・学会前のテストモードの操作ができます

## ファイル

| ファイル | 内容 |
|---|---|
| `index.html` | アプリ本体（日程データもこの中にあります） |
| `config.js` | Supabase の接続情報（URL と Publishable key / anon key） |
| `supabase-setup.sql` | Supabase のデータベース初期設定（専用スキーマ `staff_checkin`） |
| `tools/smoke_test.py` | デモモードでの自動動作確認 |

`config.js` が空のまま `index.html` を開くと **デモモード** で動きます（端末内だけの見本）。

## セットアップ手順（管理者）

この Supabase プロジェクトは他のシステムと共用しています。**このシステムのデータは専用のスキーマ `staff_checkin` に置き**、
他のシステムの設定は消さない・変えないように進めます。

### 1. データベースを作る
1. Supabase ダッシュボード → **SQL Editor** を開き、`supabase-setup.sql` の全文を貼り付けて **Run** します。
   （`drop policy if exists` の行で「destructive operations」の警告が出ますが、消えるのはこのシステムの許可設定だけです）
2. **Project Settings → Data API → Exposed schemas** に `staff_checkin` を**追加**して保存します（既にある名前は消さない）。

### 2. 最初の管理者を登録する
SQL Editor で、次の1行を **自分のメールアドレス（小文字）** に書き換えて実行します
（個人のアドレスはこの公開リポジトリには書かないため、別に実行します）。
```sql
insert into staff_checkin.members (email, is_admin) values ('自分のアドレス', true)
on conflict (email) do update set is_admin = true;
```

### 3. ログインメールの設定
**Authentication → URL Configuration**
- **Redirect URLs** に公開URL（`https://<ユーザー名>.github.io/<リポジトリ名>/`）を**追加**します。
- **Site URL は変更しません**（他のシステムが使っています）。

**Authentication → Emails → SMTP Settings**
Supabase 標準のメール送信は「1時間に2通まで・プロジェクトのメンバー宛のみ」の試験用です。
Custom SMTP（Resend・Brevo など）が未設定なら設定します（既に設定済みならそのままで構いません）。
**Authentication → Rate Limits** のメール送信数の上限も、スタッフの人数に合わせて確認します。

**Authentication → Emails → Templates →「Magic Link」**（任意）
本文に確認コード `{{ .Token }}` があると、メールアプリ内のブラウザでリンクが開いてしまう人も、
普段のブラウザにコードを入力してログインできます。**テンプレートは他のシステムと共通**なので、
システム名を入れない文面にしてください。例：
```html
<p><a href="{{ .ConfirmationURL }}">ここを押してログイン</a></p>
<p>確認コード：{{ .Token }}</p>
```

### 4. 接続情報を config.js に入れる
Supabase の **Project Settings → API Keys** の Project URL と Publishable key（旧名称 anon key）を `config.js` に入れて公開します。
Secret key（service_role）は絶対に入れないでください。

### 5. 名簿と担当を登録する
1. 公開URLを開き、自分のメールアドレスでログイン → 氏名を入力します。
2. 「スタッフ」タブで、スタッフ候補者のメールアドレスを登録します（名簿にないアドレスにはログインメールを送りません）。
3. 「日程・担当」タブで「すべてのプログラム」に切り替え、各プログラムを開いて担当（照明係）を選び「追加」します。
   まだログインしていない人も、名簿に登録済みなら担当に設定できます。
4. スタッフ候補者にURLを伝え、**学会前日までに一度ログイン**してもらいます
   （一度ログインすれば、同じ端末・同じブラウザでは当日の再ログインは不要です）。

## 学会前のテスト期間（テストモード）
「スタッフ」タブの **テストモード（管理者）** で、日にちと時刻（例：1日目 8:20）を選んで「この時刻からテストを開始」を押すと、
**全員の画面がその学会当日の時刻から動き出します**。入室ボタン・コメントの送受信・担当の通知・日程表が本番と同じように使えます。

- 画面上部に「テスト期間中：11/20(金) 9:05 として動いています」と表示されます。
- 確認したい場面（例：2日目 12:30）へは、時刻を選んで「この時刻に設定し直す」で移動できます。
- 「テストを停止（記録は残す）」で通常の表示に戻ります。
- **「テストの記録を消去」で、入室記録とコメントをすべて消してテストを停止します（名簿・氏名・担当は残ります）。学会前日までに必ず実行してください。**
- 11/20 0:00 以降はテストモードは自動で無効になり、消去もできなくなります（本番の記録を消さないため）。

## 当日の使い方（スタッフ）
- 「いまの会場」で「第1会場」「第2会場」のボタンを押すと、その会場の現在（または次）のプログラム・担当者・在室者が出ます。
- 会場に入ったら、その会場の **入室** を押します。在室人数と名前が全員の画面に反映されます。
- プログラムが終わると自動で次のプログラムに切り替わり、もう一度「入室」を押せます。
- 自分が担当のプログラムがその会場の「次」になると、画面上部に「10:30～ 第1会場のスタッフ担当です。」と表示されます。
- 同じ時間帯に別の会場で「入室」を押すと、前の会場の入室は自動で取り消されます。
- 押し間違えたときは「退室する（入室を取り消す）」で戻せます。
- 会場名（または「この会場のコメント」）を押すと、その会場のコメント欄が開きます。入室していなくても読み書きでき、
  開かない限り内容は表示されません。未読のコメントがあると「この会場のコメント」に赤丸で件数が出ます。
  コメントはプログラムごとで、そのプログラムが終わると画面から消えます。

## 動作確認のしかた（1台だけで見る場合）
URLの末尾に `?now=2026-11-20T08:25` のように付けると、その端末だけがその日時（日本時間）として表示されます。
全員で同じ時刻を共有して試すときは、上の「テストモード」を使ってください。

## 日程を変更するとき
`index.html` 内の `RAW` という一覧を編集します。開始時刻を変えると、そのプログラムの
担当割当と入室記録の紐付けが外れるので、変更後に担当を設定し直してください。

## 注意
- 名簿に載っている人は、他のスタッフの氏名・入室状況を閲覧できます（メールアドレスの表示は管理者の画面のみ）。
- 会場内の電波が弱いと反映が遅れることがあります。画面は15秒ごとに自動更新されます。
- 更新を公開した直後は、最大10分ほど古い画面が表示されることがあります（タブを閉じて開き直してください）。
- 学会終了後に片付けるときは、SQL Editor で `drop schema staff_checkin cascade;` を実行し、Exposed schemas から `staff_checkin` を外します。
