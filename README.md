# 会場スタッフ入室ボード

第1会場（3F コンベンションホール）・第2会場（1F イベントホール）のスタッフ候補者が、
スマホで「入室」を押して、誰がどの会場に何人いるかをリアルタイムで共有するツールです。

- メールアドレスで登録 → メールに届くリンクからログイン → 初回に氏名を入力
- 時刻に合わせて各会場のプログラムが自動で切り替わり、プログラムごとに「入室」を押せます
- 各プログラムの担当（照明係）と、その担当者が入室済みかどうかを表示します
- 管理者は、スタッフ名簿の登録と担当の割当ができます

## ファイル

| ファイル | 内容 |
|---|---|
| `index.html` | アプリ本体（日程データもこの中にあります） |
| `config.js` | Supabase の接続情報（ここだけ書き換えます） |
| `supabase-setup.sql` | Supabase のデータベース初期設定 |
| `supabase-add-comments.sql` | コメント機能の追加分（旧版の setup を実行済みの場合のみ使用） |
| `tools/smoke_test.py` | デモモードでの自動動作確認 |

`config.js` が空のまま `index.html` を開くと **デモモード** で動きます（端末内だけの見本）。

## セットアップ手順（管理者・所要30分ほど）

### 1. GitHub で公開する
1. GitHub で新しいリポジトリを作り、上の3ファイルとこの README をアップロードします。
2. リポジトリの **Settings → Pages** で、Source を `Deploy from a branch`、Branch を `main` / `/ (root)` にして保存します。
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。これがスタッフに配るURLです。

※ 無料プランの GitHub Pages は公開リポジトリが必要です。このリポジトリに個人情報は含まれません
（名簿・氏名・入室記録はすべて Supabase 側に保存され、名簿に載った人しか読めません）。

### 2. Supabase のプロジェクトを作る
1. https://supabase.com でプロジェクトを作成します（Region は Tokyo 推奨）。
2. **SQL Editor** を開き、`supabase-setup.sql` の一番下の `admin@example.com` を
   **自分のメールアドレス（小文字）** に書き換えたうえで、全文を貼り付けて Run します。

### 3. 接続情報を config.js に貼る
Supabase の **Project Settings → API（または API Keys）** から次の2つをコピーし、`config.js` に貼って GitHub に反映します。
- Project URL → `SUPABASE_URL`
- Publishable key（旧名称 anon key）→ `SUPABASE_ANON_KEY`

Secret key（service_role）は絶対に貼らないでください。

### 4. ログインメールの設定（重要）
**Authentication → URL Configuration**
- Site URL：手順1のURL（例 `https://<ユーザー名>.github.io/<リポジトリ名>/`）
- Redirect URLs：同じURLを追加

**Authentication → Emails → SMTP Settings（必須）**
Supabase 標準のメール送信は「1時間に2通まで・プロジェクトのメンバー宛のみ」という試験用の制限があり、
そのままではスタッフにログインメールが届きません。Resend・Brevo などの無料枠がある
メール送信サービスを Custom SMTP として設定してください。設定後、
**Authentication → Rate Limits** でメール送信数の上限（初期値30通/時）を人数に合わせて上げられます。

**Authentication → Emails → Templates →「Magic Link」（推奨）**
本文に `{{ .Token }}` を追加しておくと、メールに確認コードも記載されます。
メールアプリ内のブラウザでリンクが開いてしまう人でも、普段のブラウザにコードを入力してログインできます。
例：
```html
<h2>会場スタッフ入室ボード ログイン</h2>
<p><a href="{{ .ConfirmationURL }}">ここを押してログイン</a></p>
<p>確認コード：{{ .Token }}</p>
```

### 5. 名簿と担当を登録する
1. 公開URLを開き、自分のメールアドレスでログイン → 氏名を入力します。
2. 「スタッフ」タブで、スタッフ候補者のメールアドレスを登録します。
3. 「日程・担当」タブで「すべてのプログラム」に切り替え、各プログラムを開いて担当（照明係）を選び「追加」します。
   （日程表は冊子と同じ時間割の形式で、－／＋ボタンや2本指で拡大・縮小できます。通常は担当を割り振ったプログラムだけが表示され、開催中のプログラムは太枠になります）
   まだログインしていない人も、名簿に登録済みなら担当に設定できます。
4. スタッフ候補者にURLを伝え、**学会前日までに一度ログイン**してもらいます
   （一度ログインすれば、同じ端末・同じブラウザでは当日の再ログインは不要です）。

## 当日の使い方（スタッフ）
- 「いまの会場」で「第1会場」「第2会場」のボタンを押すと、その会場の現在（または次）のプログラム・担当者・在室者が出ます。
- 会場に入ったら、その会場の **入室** を押します。在室人数と名前が全員の画面に反映されます。
- プログラムが終わると自動で次のプログラムに切り替わり、もう一度「入室」を押せます。
- 自分が担当のプログラムがその会場の「次」になると、画面上部に「10:30～ 第1会場のスタッフ担当です。」と表示されます。
- 同じ時間帯に別の会場で「入室」を押すと、前の会場の入室は自動で取り消されます。
- 押し間違えたときは「退室する（入室を取り消す）」で戻せます。
- 会場名（または「この会場のコメント」）を押すと、その会場のコメント欄が開きます。入室していなくても読み書きでき、
  開かない限り内容は表示されません。コメントはプログラムごとで、そのプログラムが終わると画面から消えます。

## 動作確認のしかた
URLの末尾に `?now=2026-11-20T08:25` のように付けると、その日時（日本時間）として表示されます。
事前リハーサルに使えます（入室ボタンは当日の日付のプログラムだけ押せます）。

## 日程を変更するとき
`index.html` 内の `RAW` という一覧を編集します。開始時刻を変えると、そのプログラムの
担当割当と入室記録の紐付けが外れるので、変更後に担当を設定し直してください。

## 注意
- 名簿に載っている人は、他のスタッフの氏名・入室状況を閲覧できます（メールアドレスの表示は管理者の画面のみ）。
- 会場内の電波が弱いと反映が遅れることがあります。画面は15秒ごとに自動更新されます。
